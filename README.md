# Whippany Fantasy Football League (WFFL) Website

A free, static website for the WFFL — current standings, career stats, league
history/champions, a full record book, head-to-head matchups, and the league
constitution.

**Right now the site is running on fabricated sample data** (see "Sample data"
below) so it can be previewed end-to-end before real history is imported.

## Site map

- **Home** (`index.html`) — current season standings + championships won per owner.
- **Draft Central** (`draftcentral.html`) — live countdown to the draft, draft
  order, keepers, and any trades affecting draft picks.
- **Stats** (`stats.html`) — directory of every manager (click through to their
  profile) plus the all-time standings table.
- **Manager profile** (`manager.html?id=<ownerId>`) — one manager's career record,
  championships, year-by-year history, and head-to-head vs. every opponent.
- **Records** (`records.html`) — the record book: most/fewest points in a game or
  season, biggest blowout, closest game, longest win streak.
- **Head-to-Head** (`headtohead.html`) — an all-time win/loss grid between every
  pair of managers.
- **History** (`history.html`) — Hall of Fame (championship counts) and champions
  by season.
- **Constitution** (`constitution.html`) — league rules, plus a "League Settings"
  box that's auto-pulled from Sleeper (scoring, roster size, playoff format) so it
  never goes stale.

## How it works

- The site itself is plain HTML/CSS/JS, no build step, no framework. Every page
  reads from the single data file `data/league-data.json`.
- `scripts/fetch-sleeper-data.mjs` is a Node script that calls Sleeper's public
  API, walks the league's history backward (via `previous_league_id`), pulls
  standings/champions/**week-by-week game results** for each season, and
  regenerates `data/league-data.json`.
- `scripts/lib/aggregate.mjs` turns those per-season game logs into everything
  derived: all-time standings, championship counts, the record book, and the
  head-to-head grid. Both the Sleeper fetch script and the future Excel importer
  share this same logic, so the two data sources produce identical site behavior.
- `.github/workflows/update-data.yml` runs the fetch script automatically every
  day (and can be triggered manually) and commits the result — so the site stays
  current without you doing anything, once it's live on real data.

## Sample data (current state)

`data/league-data.json` is currently filled with data generated by
`scripts/dev/generate-sample-data.mjs` — a **dev-only tool**, not part of the
production pipeline. It fabricates a realistic 2012–2025 league (12 managers,
full game-by-game results) so every page has something real to render. The site
shows a yellow banner on every page whenever `isSampleData: true`, so it's never
mistaken for real data.

Once real data is in place (see next section), running
`node scripts/fetch-sleeper-data.mjs` will overwrite this with real Sleeper data
and set `isSampleData: false`, making the banner disappear.

## Bringing in real data

Two data sources are expected:

1. **Sleeper (2025–present)** — via `scripts/fetch-sleeper-data.mjs`, either run
   manually or by the scheduled Action once this is live on `main`.
2. **Excel import (2012–2024)** — an importer script that reads the league's
   historical spreadsheet and writes seasons into the same schema (marked
   `"source": "excel"` or `"manual"` so the Sleeper fetch never overwrites them).
   This script will be added once the spreadsheet is provided.

### The manager identity problem

Sleeper knows managers by their Sleeper username/display name. The Excel sheet
knows them by real first name. Those two won't match on their own, which would
otherwise split one person's career into two separate "people" — one with their
Sleeper seasons, one with their Excel seasons.

`data/manager-map.json` fixes this by giving each real person one stable
`personId` that both data sources resolve into:

```json
[
  {
    "personId": "p1",
    "canonicalName": "Alex",
    "sleeperUsernames": ["AlexSleeperHandle"],
    "excelNames": ["Alex"]
  }
]
```

- `canonicalName` is what the site displays everywhere, regardless of what
  someone's Sleeper display name or team name happens to be.
- `sleeperUsernames` matches against that person's Sleeper username *or*
  display name (case-insensitive) — list any variants they've used.
- `excelNames` matches against however they appear in the historical
  spreadsheet.

**To fill this in**, provide a list of all 12 managers as: their real first
name → their Sleeper username (or the display name shown in the league). The
fetch script warns (in the Action's log) about any Sleeper manager it can't
find in the map, so gaps are easy to spot. Until someone is mapped, they still
show up on the site under their raw Sleeper identity — nothing breaks, their
history just won't merge with pre-Sleeper seasons yet.

## One-time setup

### 1. Enable GitHub Pages (free hosting)

In this repo on GitHub: **Settings → Pages → Build and deployment → Source**,
choose **"Deploy from a branch"**, pick the `main` branch and `/ (root)` folder, then Save.
GitHub will give you a URL like `https://<your-username>.github.io/PBI_Reports/`.

### 2. Merge this branch to `main`

The scheduled Action only runs on the default branch (`main`), so once this work
is merged there, the daily auto-update will kick in (once you're ready to move
off sample data — see below).

### 3. When you're ready to go live with real data

Trigger the fetch: **Actions** tab → **Update League Data** → **Run workflow**
(or wait for the daily schedule). This overwrites the sample data with real
Sleeper data for whatever seasons your league played there.

## Running scripts manually

```bash
# Pull real data from Sleeper (requires Node 18+)
node scripts/fetch-sleeper-data.mjs
# or explicitly: node scripts/fetch-sleeper-data.mjs <leagueId>

# Regenerate the sample/placeholder data (dev tool, not for production use)
node scripts/dev/generate-sample-data.mjs
```

## Pre-Sleeper history

The Sleeper fetch only finds seasons that exist in Sleeper's league chain. Older
seasons (paper standings, another platform, etc.) come in via the Excel import
mentioned above, or can be added by hand to the `seasons` array in
`data/league-data.json` using the same shape as Sleeper-sourced entries, with
`"source": "manual"` set — the fetch script preserves any non-Sleeper season it
finds and won't overwrite it.

### Season shape

Each entry in `seasons` looks like this (this is also the shape the Excel
importer will produce):

```json
{
  "year": 2013,
  "leagueId": null,
  "status": "complete",
  "name": "WFFL 2013",
  "source": "manual",
  "standings": [
    { "ownerId": "m1", "managerName": "...", "teamName": "...", "wins": 11, "losses": 3, "ties": 0, "pointsFor": 1520.4, "pointsAgainst": 1310.2, "rank": 1 }
  ],
  "champion": { "ownerId": "m1", "managerName": "...", "teamName": "..." },
  "runnerUp": { "ownerId": "m2", "managerName": "...", "teamName": "..." },
  "games": [
    {
      "week": 1,
      "isPlayoff": false,
      "teamA": { "ownerId": "m1", "teamName": "...", "score": 123.4 },
      "teamB": { "ownerId": "m2", "teamName": "...", "score": 110.2 }
    }
  ],
  "settings": { "numTeams": 12, "playoffWeekStart": 14, "playoffTeams": 6, "rosterPositions": [], "scoringSettings": {} }
}
```

`games` is what powers the Records and Head-to-Head pages — without it, those
pages will just be empty for that season (standings/champions still work fine).
`ownerId` must be a stable, consistent identifier per manager across every
season (Sleeper's `user_id` for Sleeper seasons) so career stats and
head-to-head add up correctly across years.

## Draft Central

The Draft Central page pulls most of its content straight from Sleeper's draft
API each time the fetch script runs:

- **Countdown & draft order** — from the league's draft object (`start_time`,
  `draft_order`). Updates automatically as soon as your commissioner sets a
  draft date/time and order in Sleeper.
- **Trades affecting the draft** — from Sleeper's traded-picks list, filtered
  to the upcoming season.

**Keepers have no equivalent in Sleeper's API** — most leagues track keeper
rules and costs outside the platform, so this one's entirely manual. Edit the
`draftCentral.keepers` array directly in `data/league-data.json` (the fetch
script never touches it, so it survives every auto-update):

```json
{
  "draftCentral": {
    "keepers": [
      { "ownerId": "p1", "teamName": "...", "playerName": "...", "round": 4, "notes": "" }
    ]
  }
}
```

`ownerId` should match the `personId` you used in `data/manager-map.json` so
the keeper links to the right manager's profile.

## Proposed rule changes / discussion items

The Constitution page also has a manually-maintained "Proposed Changes for
Next Season" section — for rule changes already decided, and separately for
open items to discuss/vote on. Edit `constitutionUpdates` in
`data/league-data.json` (preserved across every auto-fetch, same as
`constitutionText` and `draftCentral.keepers`):

```json
{
  "constitutionUpdates": {
    "ruleChanges": ["Playoff field expands from 6 to 8 teams starting next season."],
    "discussionItems": ["Vote on switching from Half PPR to Full PPR scoring."]
  }
}
```

Each list is just plain strings — add, remove, or reword freely. Leave a list
empty (`[]`) or omit `constitutionUpdates` entirely if there's nothing to note.

## Customizing

- League name: edit `leagueName` in `data/league-data.json` (persists across auto-fetches).
- League constitution text: edit `constitutionText` in `data/league-data.json`
  (also persists across auto-fetches — the fetch script never touches it).
- Colors/branding: `css/style.css`.
- Update frequency: edit the `cron` line in `.github/workflows/update-data.yml`
  (currently once a day; you could set it hourly during the season).
